# Text-Based RPG

## Repository
https://github.com/ut4hr4ptor/hayesCarrascoSparky_FinalProject

## Description
This project will emulate a text-based game centered around making choices in a role-play style environment.
The game allows creative liberty when it comes to the player's character and their life.

## Features
- Character customization
  - The program will allow for the player to input text to name their character, choose from different character types, personality traits, and more; storing this info and implementing it into how the game functions/reacts.
- Choice-based gameplay
  - Multiple outcomes/outputs will come from stored memory regarding the player's choices and behavior during the game's base events.
- Visual displays per event
  - Artwork designed for the game's major events, such as beginning, establishing shots, endings, and the like. These will pop up when necessary.
 
## Challenges
- Being able to store so much data/user inputs while not cluttering the code.
- Making sure all choices and their effects are accounted for and not mixed up.
- Figuring out how to build the world and the story itself. Worldbuilding takes a lot of thought.
- Deciding how many artwork/images to be created and whether or not they are interactive.

## Outcomes
Ideal Outcome:
- The ideal outcome is for the program to be functional and entertaining with multiple endings that encourage the user to repeat the game.

Minimal Viable Outcome
- The bare essential would be for a playable game that focuses on creative customization with a goal of at least two different endings.

## Milestones

- Week 1
  1. Figuring out what characters/settings/main events will be utilized.
  2. Laying down the basic information of the first goal and researching/translating it into code.
  3. Consulting with TA as necessary.

- Week 2
  1. Continuing to do research and take examples from sources of inspiration (ex: Undertale, Telltale Games, dating simulators) and figuring out how to recreate these programs.
  2. Drawing the digital art necessary for different scenes in the game, polishing them throughout the week.
  3. Consulting with TA as necessary.
 
- Week N (Final)
  1. Continuing to add different outputs per different inputs and tweaking the code as needed, aiming for two endings minimum.
  2. Programming the digital art into the game to be triggered as required of each scene.
  3. Consulting with TA as necessary, doing final test playthroughs and fixing any errors.
